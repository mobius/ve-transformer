# 下一阶段：NLC矩阵计算并行评估

状态：只读研究与实施计划，尚未实施、编译或运行多线程NLC；分词器复用ABBA仍在执行。不能据库文件存在宣称可运行或更快。

已有测量：常驻复用初验热请求约22.4秒，CLIP图约1.5秒；此前四步常驻热请求VAE图约13.75秒，其中BLAS约8.28秒。两者不是同一轮性能对照，不能直接作收益百分比。固定ggml-blas核心直接调用cblas_sgemm；当前构建链接NLC顺序库，Generic路径无NLC线程数设置。

本机存在NLC3.1.0的libblas_sequential、libblas_openmp和libcblas。本机CPU、VE及运行时支持由前轮温度保护下的槽1完整推理证实；下一轮实施前仍重新检查环境和温度，重型负载严格串行。

官方依据：[NLC3.1编译与链接](https://sxauroratsubasa.sakura.ne.jp/documents/sdk/SDK_NLC/UsersGuide/main/en/c_linking.html)要求CBLAS多线程使用-lcblas -lblas_openmp -fopenmp；[BLAS指南](https://sxauroratsubasa.sakura.ne.jp/documents/sdk/SDK_NLC/UsersGuide/blas/f/en/index.html)说明OpenMP版线程数由OMP_NUM_THREADS指定。当前NCC5.4满足该指南列出的5.0及以上版本要求，但具体组合必须实际运行验证。OpenMP是多线程计算接口，术语表已有解释。

实施顺序：先完成分词器复用全部验收并归档当前二进制；提取真实CLIP/UNet/VAE矩阵尺寸与耗时，避免小矩阵单一测试代替完整图。项目build下单独创建顺序和多线程矩阵探针，冻结输入，以独立高精度参考检查，测1/2/4/8线程与冷/热执行，同时观测温度/风扇；不能并行启动多组。

随后再为独立图像构建增加显式NLC库模式，保留旧构建目录及库配置；不要全局安装或改默认服务。仅调整BLAS链接及运行线程设置，固定其余算子与共享池。共享池与NLC运行时都可能保留线程，需确认实际运行/休眠和资源占用；线程数设置不等于有效并行，也不预先认定长等待原因。

完整候选验收需单步/四步CPU对照、多提示词、内存恢复、实际BLAS分配证明、阶段耗时与串行对照，覆盖运行时交接开销。浮点归约次序可能改变，按独立CPU容差及有限值判据验收，记录与旧路径的差异；不承诺按位一致。若完整请求不更快，不采用候选。

本轮研究报告：性能前后、正确性、温度和风扇均待实际候选验证；上述性能只用于选目标。生产并发、其他尺寸和模型仍未验证。下一步先收尾分词器复用，再运行受温度保护的矩阵探针。

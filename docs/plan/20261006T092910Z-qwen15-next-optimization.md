# 下一轮单VE性能优化计划

当前验收基线：Qwen2.5-1.5B-Instruct Q4_K_M，单VE运行槽1、4线程、上下文2048。生成4.5019词元/秒；17输入/32输出热态往返8.4064秒；117输入/16输出9.3750秒。保持FP64投影/精细元素计算、FP32激活与原注意力F16舍入，缓存载荷11.50GiB、预算16GiB。只有本机单卡这些负载有证据，不将结果扩展到其他模型或三卡。

本次只提交进展和制定计划，不启动下一轮性能实验。实施前环境复查：96逻辑CPU、ASPEED显示控制器、3个VE槽及VEOS可访问，NCC/uv可用；温度守护可读，CPU/ve0峰值63/44.12°C。设备枚举不能代替执行检查；后续实验仍先运行温度守护下的VE smoke验证。BMC风扇不可读，97个可读通道本次无变化，不据此判断真实风扇策略。

## 第一阶段：投影分块与线程组合

保留当前1024行/4线程执行器及哈希作为不可变基线。独立构建512、1024、2048行投影候选，反量化子块固定最多128行；再对入选块大小测2/4/8线程，不预先承诺哪组最快。先短负载筛选，仅有精度和速度证据的候选进入完整对照。

固定17输入/32输出、117输入/16输出，增加129/257输入边界案例以覆盖128词元输入批次及末尾单列回退；补充128输出的较长生成。输入长度以VE分词实测值为准，通过构造和计数确认，不能用字符数替代。主指标生成词元/秒及热态请求往返，辅助指标输入/模型生成/选择/分词计时、冷启动、缓存命中/拒绝/保留量。各线程缓存几何不同，每个进程独立预热，不共享前组热态缓存。

## 第二阶段：缓存查找与打包成本

先用单独诊断运行测量缓存查找、锁等待、输入打包与BLAS调用次数/耗时，判断相对成本；诊断计时会影响调度，正式性能关闭这些计时。源码显示全局互斥锁和有序表查找，这是待测假设，不能宣称已经是主要瓶颈。

若证据支持，实验每工作线程的缓存快速查找路径或更直接的索引。必须保证模型切换、地址复用、预算变更、清空及线程池销毁时引用正确失效；本地引用不能在清空后暗中保持大权重并绕过预算。统计读取不能与更新产生数据竞争，命中计数仍准确。保留预算为0、预算不足时的原计算回退，避免以丢弃统计或取消容量限制换取速度。

## 第三阶段：独立精度/存储实验

前两阶段完成后，再评估FP32权重缓存与FP32投影计算。FP32存储和FP32累加是两项不同改变，分别验证；FP32缓存临时展开为FP64可能增加成本，不预设收益。RMSNorm、激活函数及注意力舍入先保持当前策略。每一数学模式写入独立构建清单、执行器标识和结果，避免仍标为全FP64投影。失败候选保留证据，不进入默认入口。

## 验收与停止规则

- 每个候选先独立矩阵/尾块/广播/步长与缓存契约验证，再三提示24步完整词表对照：最大绝对误差≤0.1、RMSE≤0.01、最大分数词元一致24/24。
- 新增129/257输入、长生成需先建立参考，完整分数对照或明确标注仅输出序列一致；不能将旧短提示验收当作新长上下文精度证明。至少覆盖连续短→长→短、EOS自然终止、正常EOF和协议错误。
- 最终性能按基线/候选/候选/基线顺序，各进程独立冷请求与至少3个热请求。报告全部样本、各轮中位数及波动；主要目标生成或请求耗时改善至少5%，其余关键负载不回退超过2%。低于此阈值记录为未形成稳定收益，不自动采纳。
- CPU80/85°C、VE70/75°C警告/停止；所有硬件测试持续使用temperature_guard，温度缺失立即停止。观察可读风扇，不改配置，BMC不可读明确留档。串行硬件任务，避免测速被其他实验干扰。
- 不新增全局软件；必要依赖先用项目uv环境。所有阶段分别留research/plan/impl/architecture的UTC时间戳文档，新增术语写glossary；发布前审计确切暂存内容，不提交模型、日志、凭据、私人路径或设备序列号。

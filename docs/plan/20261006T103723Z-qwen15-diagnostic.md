# Qwen 1.5B 诊断计时

实施前硬件检查：96 个 CPU 逻辑线程、ASPEED 显示控制器、三张 VE 运行设备；温度 CPU 67°C、VE 最高 43.88°C。实际执行仍需守护下验证。

构建独立 control/profile 执行器，均保持 1024 行、4 线程、FP64。计时仅在 QWEN_PROFILE 下编译，默认路径无计时开销。每个 GGML 工作线程持有独立计数槽，主线程只在计算结束后快照；计时累计值是工作线程耗时之和，不等于墙钟耗时。单列与多列分开统计。先矩阵/缓存验证，再 CPU 全分数检查及 ABBA 开销对比。当前尚无诊断或收益结论。

首次逐次计时 AB 样本：无计时约 4.495 token/s，计时约 3.311 token/s，退化约 26.35%。主动通过温度守护停止后续复测，原结果不完整且不用于瓶颈判断。保留原二进制与源文件快照，改为分散抽取约 1/64 分块计时；未抽中分块不读取时钟。抽样结果按采样概率估计线程累计耗时，并明确不等于墙钟或全部算子覆盖。

抽样起点采用线程独立偏移，避免多个工作线程同时读取时钟导致锁等待估计偏大；初步抽样任务在完成前停止，不用于性能结论。增加空时钟对校准和每项实际计时次数，保留原始值及扣除时钟中位开销的近似估计。校准构建 CPU 最高 81°C，触发警告但未达 85°C 停止；不改变阈值或风扇。

最终抽样版已通过三组、共 24 步 CPU 全分数检查：最高分词元全部一致，最大误差 0.0258684，RMSE 最大 0.00362810。ABBA 正在进行。首组抽样估计：单列输入整理约占已计时阶段 60%，缓存锁等待与查找合计约 7.5%；不代表全部算子占比，不据此宣称性能提升。

最终验证：ABBA 完成，每个进程一次冷请求、三次短 warm 请求、一次长请求、一次返回短请求。无计时对照 4.524158 token/s，抽样 4.521149 token/s，生成速度变化 -0.0665%；短请求总耗时变化 -0.1363%。这些是诊断开销对比，不是推理优化收益。三组共 24 步 CPU 全分数门槛通过，32 步 CPU 序列与长请求既有 VE 序列一致。缓存预算、归零的预留容量、warm 无新增缓存条目均通过。

构建 CPU 峰值 81°C，触发 80°C 警告但未达 85°C 停止；构建 VE 峰值 47.12°C。最终推理 CPU 73°C、VE 51.88°C。风扇 97 个可读通道零观察变化，BMC 数据不可用，不能证明策略稳定。所有工作在运行槽 1；不宣称多卡推理验证。默认执行器、线程、算术精度和会话协议保持已验证版本。未重复本轮未变化的 129/257 输入、128 生成、自然结束和协议错误测试；这些引用上一轮覆盖，不能算作诊断版新增验证。

下一轮优先设计显式候选模式：在每个投影算子的每个工作线程内，把同一输入的 FP32→FP64 转换与复制从行分块循环中提到循环外，复用只限当前算子，避免跨请求沿用激活值。保持 FP64 累加、128 行量化解码子块和现有缓存预算。限制额外工作区大小并保留 MoE 原路径；独立候选目录不覆盖默认。矩阵/缓存、24 步全分数、32 步序列、117 长输入、129/257 输入及 128 输出边界全部验证，再同轮 ABBA。达到至少 5% 稳定收益且关键负载无超过 2% 退化才考虑采用。尚未实现或测量该候选收益。

# 统一OpenMP线程切换探针

上一轮广播加乘正式ABBA热请求18.157→13.943秒、下降23.21%，102项CPU检查；VAE矩阵仍约5.95秒。本轮先测单一OpenMP运行时8↔4成本，避免重现旧OpenMP+pthreads混合方案的逐图停滞。

环境：宿主96逻辑CPU、ASPEED显示、三VE槽设备/VEOS套接字可见，前轮槽1实际执行。实施前温度/风扇守护查询进行中。独立原生NCC C探针，与现有模型构建隔离，不改原模型二进制；低占空比编译25%，运行无CPU限速，测试串行。

探针只使用同一个OpenMP运行时及OpenMP NLC，比较固定8/8/8与8/4/8循环，按固定/切换/切换/固定相位执行；每相位预热1循环、测量4循环。使用真实VAE代表矩阵m512/n16384/k4608、N/T布局、相同行跨度，数据为精确可验证的合成FP32常量行；全输出每次检查，另一个整数并行工作校验区域实际人数。分别计线程配置、区域进入/执行、矩阵时间及退出线程上限。

线程容量不等于NLC内部实际利用率，空区域/整数工作及合成矩阵不等于完整模型；探针比旧混合方案更接近统一运行时，但尚未整图或临时工作区交接验证。只有切换成本合理才实施匹配的阶段通用/NLC线程，不凭微基准宣称整图收益。温度/风扇/内存连续监控，所有原数据与每轮报告留档。

## 本轮探针报告：通过

60次代表矩阵与整数区域检查通过，完整检查503316480个输出，实际线程人数及退出上限全部匹配。固定8区域/配置合计约0.014毫秒；8→4均值0.352毫秒、最大0.542毫秒，4→8均值8.142毫秒、最大8.635毫秒。中间代表矩阵固定8均值0.165813秒、4线程0.115399秒；这些是合成代表矩阵计时，不是完整VAE收益。切换成本足够低，可继续实施匹配阶段线程候选。

构建CPU64°C/VE42°C，测试CPU60°C/VE46.12°C，97风扇状态通道无变化，节点采样最高1.884765625GiB、退出128MiB。原模型二进制与旧已验证摘要相同。新阶段模型仍未实施/验证，不能宣称模型收益。数据见[机器结果](../results/20261009T105426Z-ve-omp-switch.json)。

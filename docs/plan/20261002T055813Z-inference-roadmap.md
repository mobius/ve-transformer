# 迭代 001：推理路线

用户确认用途为推理，允许从最简单模型开始，以性能指标逐步优化，推进到更现代框架。

1. 初始化 Git、开发约定、过程文档和术语；检查实际硬件能力。
2. 用固定参数的最小 Transformer 层验证 CPU 正确性，编译 VE 版本。当前已完成；VE 执行受环境阻塞。
3. 设备可访问后，在三个节点分别对比数值结果，记录编译器、形状、延迟、吞吐量、内存使用和重复测量分布。先单卡，不自动占满三张卡。
4. 扩展形状矩阵，找到主要耗时；评估复用临时缓冲区、NEC 数学库矩阵乘法、数据布局和注意力计算优化。每次变化必须保留数值验证与前后基准。
5. 增加可读取权重的小模型和端到端推理；明确模型结构、许可、权重来源及质量验证数据。
6. 根据可用的软件兼容性选现代框架接入路线，验证具体模型支持再决定后端；不假定通用框架原生支持 NEC VE。

后续 Python 依赖优先 uv 创建项目内环境。当前无依赖安装。预训练模型尚未指定，先不下载大型模型或实现未经选择的框架适配。

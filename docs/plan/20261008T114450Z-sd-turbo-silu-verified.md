# SD-Turbo SiLU 优化验收

单VE运行槽1，官方SD-Turbo固定修订，FP32、512×512、8线程常驻池、单提示单步ABBA：全进程均值216.835→167.596秒，延迟下降22.708%；图执行145.630→96.387秒，下降33.814%；VAE图执行90.688→44.506秒，下降50.924%。权重加载约57.8秒基本不变。各组两次，包含权重加载与诊断输出，文件缓存未控制，不是常驻稳态秒/图。见[公开结果](../results/20261008T114450Z-sd-turbo-silu.json)。

四次各五项CPU参考比较通过；额外四步11项与四个时间步通过，进程326.387秒，解码归一化L2误差1.783690e-6，四步没有ABBA不报告其提速百分比。七种长度的SiLU极端值/FP64/原地/尾部哨兵测试及当前12算子回归通过。浮点舍入与原实现有细微差异，不能声称逐字节相同。实际候选图像已目视检查，未建立图像质量基准。

全部硬件任务串行温度监督。本轮CPU最高80°C触发警告但未达85°C停止线，VE最高53.25°C低于70°C警告；各轮97个可读风扇通道未观察到变化，不能推断完整风扇策略固定。未测物理HBM峰值。模型权重仍逐组件加载。

实现只改图像专用SiLU：独立O2循环、禁用标量fast-math、禁止重排和倒数替代、启用向量数学范围检查及直接除法；编译诊断明确确认向量化。第一版缺少向量范围检查而失败，已记录拒绝，不纳入性能结果。LLM后端和vendor保持隔离。检查器默认generic，已验证工作负载推荐显式 `--threadpool persistent --profile --silu ve`。使用步骤见[图像指南](../guides/sd-turbo.md)，中间记录见[SiLU迭代](20261008T111611Z-sd-turbo-silu.md)。

## 下一轮顺序

1. 先优化UNet Softmax的指数计算：隔离批量exp循环并使用已验证的NCC数学安全选项；保留原最大值处理、求和精度及归一化逻辑。独立FP64测试覆盖77和4096元素、向量尾部、极端分数差及掩码，再进行匹配ABBA与四步验收。
2. 再优化VAE im2col：根据源/目标布局调整循环顺序、提取边界和填零逻辑，以精确数据复制为验收目标；覆盖步幅、膨胀、填充、奇数尺寸和批量，保留不支持布局的通用回退。
3. 决定默认启用前扩大到六提示验证；逐项测量，不将两个候选混作单项收益。
4. 算子稳定后测真实HBM占用与工作区，再设计权重常驻，单独报告首次请求和后续请求延迟。

全部步骤先判断运行环境、串行温度监督并观察风扇，不提前宣称向量化或提速。

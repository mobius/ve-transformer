# 完成单 VE 图像验证的计划

实施环境判断：运行槽位 1 的基础算子已经实跑；CPU、VE 温度监控有效，可继续受监控的编译与推理。CPU 参考已串行限速完成，完整模型尚未在 VE 上运行。

1. 保留已通过的基础算子结果，局部降低耗时转换模块的 NCC 编译优化级别；图像计算核心保持既定 FP32 配置，激活使用官方一致的 erf 公式。
2. 完成独立框架 CLI，记录二进制、上游提交与所有生成适配文件的 SHA256。
3. 读取已完整完成的 CPU 512×512 单步参考，以相同初始噪声、噪声强度和时间步验证原生文本编码、U-Net、调度与 VAE。
4. 达到阶段阈值后扩大公开提示与四步覆盖；失败先定位具体阶段，不放宽阈值使之通过。
5. 正确性通过后才测常驻性能、工作区峰值及优化；初次启动、模型加载和导出数组的耗时不充当稳态性能。

全程使用温度守护；CPU80/85°C、VE70/75°C，失去监控即停止。参考与重型编译串行安排，风扇配置不改变。

后续构建策略：VE 只构建本阶段必需推理能力，转换 API 明确拒绝，CPU 构建仍使用上游转换实现。持续温度监控下的单任务编译占空比改为75%，参考保持25%；若温度触发停止则退出，不提高阈值。

完整构建前对齐 U-Net 残差/输出归一化稳定常数；注意力/VAE 的不同值保留。独立算子编译显式与框架统一 GGML_MAX_NAME=160，最终框架构建后再核对算子与完整阶段。

VE 基础文生图范围不含模型转换和自动检测修图，公开可选接口明确拒绝；构建完毕须检查拒绝行为，不能静默接受请求。此范围限制不降低完整 SD-Turbo 文本编码、U-Net、VAE 的数值门限。

# SD-Turbo 公式与算子核对

环境支持：本机 x86 主机提供编译与参考执行；ASPEED 仅显示；运行槽位 1 已实际执行本轮原生 VE 算子，不能由枚举推断其他功能通过。三组件官方 FP32 权重有效载荷约 4.805 GiB，工作区尚未测量。

固定框架的 SD2 文本编码器默认执行 23 个 Transformer 层，与官方配置一致，填充词元 ID 为 0。须使用 epsilon 预测，正向条件单分支；原生 CFG=1 对应参考不使用无条件混合，数值参数不是直接照搬。

原始 `ggml_ext_gelu` 使用 tanh 近似，通用实现还经 FP16 查表；官方 SD-Turbo 的文本编码和 GEGLU 使用 erf GELU。生成局部替换，使用已有 FP32 erf 算子；当前算子测试已验证这一计算，但完整图像模型仍待重编译及逐级比较。

基础算子 11 项在 VE 上通过：两个 NLC 矩阵尺寸（257×65×77 与 1024×1024×77）、三个卷积用例（含 37×29 奇数边界、步长 1/2 与 64×64×4→320 首层尺寸）、层/组归一化、SiLU、erf GELU、softmax、最近邻上采样。独立标量 FP64 公式作参考，归一化 L2 阈值 1e-4；当前最大数值偏差量级约 2.09e-7。没有性能测试或加速结论。

NEC 编译器的 GGUF 读取模板已通过显式 constexpr 两分支适配；转换模块 O1 编译较慢，人工终止本项目该编译进程，改该模块 O0。并非温度故障，亦无证据声称编译器在该模块崩溃。

转换模块 O0 仍耗时较长，最小标准正则代码能完成编译，不能将问题简单归因于所有正则不支持。当前推理直接读取官方分组件 FP32 权重，不需要转换 API；故 VE 一期构建排除该可选实现，转换命令明确报错。没有替代或伪造推理算子。

归一化配置进一步核对：框架 GroupNorm32 默认1e-6，官方 U-Net 残差及最终输出归一化为1e-5；注意力前组归一化和 VAE 则仍为1e-6。生成局部头文件允许传入稳定常数，只调整对应 U-Net 残差/输出层。差异不能通过统一改所有归一化层解决，须由完整参考验证。

自动检测修图是另外加载检测模型、生成局部区域并再次修图的可选流程，不属于本轮 SD-Turbo 基础文生图。对应编译单元也长时间停留在模板代码生成，人工终止后在 VE 构建明确禁用；核心权重读取与三个神经网络继续实际编译，不替换神经网络计算。

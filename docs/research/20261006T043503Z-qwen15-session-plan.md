# Qwen1.5B计时与连续请求

主机环境确认CPU96逻辑核、三张VE的运行槽/VEOS可访问；后续构建和推理都由温度守护包装，观察可读风扇，不修改配置。现有执行器已经在VE调用llama_tokenize，旧回答将其归于主机不准确。

增加模型加载、分词、状态重置、输入处理、模型逐步计算、选择词元、文本转换、请求总时间。缓存建立报告各工作线程分配/转换耗时之和，不能称为墙钟时间或解码全部代价；首次与热态请求仍分别实测。连续模式只加载一次模型/上下文并复用缓存，请求之间清理生成状态，串行处理。协议为8字节小端长度/生成步数头加UTF-8提示，输出逐行JSON；限制请求大小、容量并在不完整帧时退出。

独立构建session执行器，保留已验收1.5B和35B二进制。验收：三提示完整词表对照，变长请求与旧执行器输出一致，重复请求缓存复用，截断/超容量失败，首次与热态时间/分词占比，独立算子采样运行。无新增全局依赖。

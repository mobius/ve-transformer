# im2col输出行划分候选

前轮实际形状确认VAE每请求40次、11种形状、19.391GiB逻辑输出，512×512两种形状占约58%。本轮先保持原排列、向量宽度方向及填充公式，将线程所有权从输入通道改为连续输出行区间；不同线程区间互不重叠。不是连续标量输出方案，不改变模型当前实现。

实施前温度监控检查CPU60°C、VE最高42.38°C，97可读风扇通道无变化；运行接口存在、最近槽1原生双请求通过。CPU80/85、VE70/75持续保护，缺失读数停止。独立候选单独编译，不修改模型对象，不安装、不调整风扇、不提交。

先以标量独立参考检查原8种边界形状、1/8线程、NaN/Inf/负零按位结果及输出哨兵；顺序调用只证明划分组合结果，后续还需并发所有权与真实512形状微基准，才可判断性能。当前收益尚未测量。

下一步：候选正确性通过后，在真实128/256通道512形状上用同一OpenMP运行时比较原实现与输出行划分，验证并发输出及输入保护；记录重复耗时、温度和风扇，再决定是否接入整图。

独立VE运行退出0，8种形状×1/8线程共16个按位参考/输出哨兵用例通过。CPU峰值60°C、VE峰值41.50°C，97可读风扇状态无变化。[机器结果](../results/20261009T123747Z-sd-turbo-im2col-rows.json)记录源代码、对象、可执行文件及日志摘要。

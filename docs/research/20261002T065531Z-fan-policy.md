# 迭代 009：CPU 温度策略与风扇可观测性

用户允许提高 CPU 测试温度并要求观察风扇策略。实施前 CPU 与 VE 温度可读取；coretemp 两个封装均报告高温阈值 88°C、临界值 98°C。选择 CPU 80°C 警告、85°C 停止，VE 保持 70°C/75°C。仅修改项目监督器，不修改硬件限制。

只读调查：nct6793 的 6 个 fan 输入均为 0 RPM；5 个 PWM 输出均为 127，pwm_enable 均为 1、pwm_mode 均为 1。根据 Linux 驱动文档，enable=1 表示手动控制模式、mode=1 表示 PWM 输出。不能将这些未确认对应物理风扇的通道视为真实机箱风扇转速，0 RPM 不等于风扇停转。

参考：https://docs.kernel.org/hwmon/nct6775.html 。自动曲线节点虽然存在，但当前 enable=1，不据其曲线推断自动调速正在生效。

NEC 风扇控制及其监控服务均 active/running。服务活动状态只说明服务运行，不能证明风扇策略、转速或调速效果。VE1 fan_rpm 对应 sensor_29，但本机读取通常不可用，监督器记录 unavailable。

BMC IPMI 设备存在但只允许 root。只读 sudo -n ipmitool sdr 查询需要密码，未能获取实际 BMC 风扇/温度数据；没有请求密码、修改权限或运行风扇控制命令。已向用户询问可选的只读查询结果或已有免密监控入口，仍继续可完成的 sysfs 观察。

完成同一终端授权后的实际负载和5秒冷却观察：104个通道，CPU峰值68°C，VE峰值42.75/39.12/41.25°C。BMC前置风扇1在3800和3900 RPM之间变化，结束回到3800；其余已采样风扇转速及sysfs控制值和NEC服务状态无观察到变化。不能由100 RPM变化判定内部策略变更。首次跨终端查询没有可用sudo缓存，明确记为unavailable；随后同终端授权读取成功，无权限配置修改。

BMC解析与超时模拟测试、原温度保护测试通过。代码/文档敏感信息扫描及git diff --check通过；原始采样在忽略的build/results中。

# 技术词汇

| 术语 | 说明 |
| --- | --- |
| Agent | 执行开发工作的 AI 助手；本项目使用 OpenAI Codex。 |
| CPU | 主机通用处理器，负责控制与通用计算。 |
| GPU | 图形处理器，部分型号可执行通用并行计算。 |
| NEC Vector Engine（VE） | NEC 向量计算卡，通过向量指令处理多个数据元素。 |
| NCC | NEC C 编译器，将 C 源码编译成 VE 程序。 |
| VEOS | VE 的操作系统配套服务；设备与服务均可访问才可能运行程序。 |
| Transformer | 使用注意力机制和前馈网络处理序列的网络架构。 |
| 前向推理 | 用固定参数从输入计算输出，不进行参数训练。 |
| 多头自注意力 | 将特征分成多个头，分别计算序列位置间的关联，再合并结果。 |
| Softmax | 把一组分数归一化为总和为 1 的非负权重。 |
| LayerNorm | 对每个位置的特征做均值和方差归一化。 |
| 残差连接 | 将模块输入加到模块输出，以保留输入信息。 |
| FFN | 前馈网络；这里由两层线性变换和 ReLU 组成。 |
| ReLU | 激活函数，负数变成零，非负数保持原值。 |
| 因果掩码 | 阻止序列位置关注未来位置的注意力限制。 |
| DNS | 将域名转换为网络地址的服务。 |
| uv | Python 包及虚拟环境管理工具。 |
| conda | 管理独立软件环境的工具。 |
| podman / docker | 容器工具，用隔离环境运行软件。 |
| float32 / float64 | 分别用 32 位和 64 位表示浮点数；参考计算用更高精度辅助检查误差。 |
| 延迟 | 一次计算所花时间；这里测单层前向调用耗时。 |
| 吞吐量 | 单位时间处理的工作量；这里指输入序列位置数，不是生成速度。 |
| 向量化 | 编译器把循环运算转成同时处理多个元素的指令。 |
| 预热 | 正式计时前运行数次，减小初次运行带来的影响。 |
| GCC / C11 | 通用 C 编译器及本项目采用的 C 语言标准版本。 |
| Q/K/V | 注意力模块的查询、键和值三个线性投影。 |
| Git 元数据 | 版本历史、索引和配置等内部数据，通常存放在 .git。 |
| 沙箱 | 限制进程可访问文件、设备和系统接口的隔离环境，可能隐藏主机设备目录。 |
| 运行槽位（veslot） | NEC 启动工具通过 /dev/veslotN 选择的运行节点，其编号不一定等于 sysfs 硬件编号。 |
| sysfs | Linux 通过 /sys 暴露硬件及驱动信息的文件接口；能读取信息不代表能使用设备。 |
| NLC / BLAS | NEC 数学库集合及其基础线性代数接口，可提供优化的矩阵乘法。 |
| AVEO | NEC 的主机端卸载执行接口，可从主机创建 VE 进程并调用卡上计算。 |
| OpenMP | 用多个线程执行并行计算的编程接口。 |
| P50 / P95 | 延迟分位数：排序后分别有约 50% 和 95% 的测量值不超过该值；重复样本过少时稳定性有限。 |
| 最近秩分位数 | 对 n 个样本升序排序，取第 ceil(p×n) 个值作为比例 p 的分位数。 |
| 校验和 | 输出数值的简要汇总；这里只求和，不能证明所有元素正确。 |
| CLI | 命令行界面，通过终端命令启动和控制工具。 |
| workspace-write | Codex 的工作区写入沙箱模式，执行仍受隔离规则限制。 |
| danger-full-access | Codex 的无本地沙箱限制执行模式，权限范围扩大到主机资源。 |
| on-request | 按需审批策略，由 agent 在必要时请求审批；与沙箱模式分别控制。 |
| SGEMM | BLAS 的单精度通用矩阵乘法接口，这里用于 float32 线性变换。 |
| NumPy | 主机侧数值数组计算库，本项目用其 float64 结果做独立参考。 |
| PyTorch | 深度学习框架，本项目支持导出部分 TransformerEncoderLayer 的参数执行推理。 |
| 前置归一化（pre-norm） | 在注意力和前馈子模块之前进行 LayerNorm 的层结构。 |
| eval 模式 | PyTorch 的评估模式，关闭 dropout 等训练期随机行为。 |
| dropout | 训练时随机置零部分特征的机制；本项目推理不执行该操作。 |
| 参数导出 | 把框架中的模型权重转换为原生执行器可读取的格式。 |
| embedding（嵌入） | 把整数编号转换为网络使用的特征向量。 |
| logits（输出分数） | 输出头给各候选编号的原始分数，尚未归一化为概率。 |
| argmax | 找到分数最大的位置或候选编号。 |
| 后端 | 执行同一计算接口的具体实现，本项目包括主机 C、基础 VE 和 NLC VE。 |
| epsilon | 归一化分母中加入的小常数，用于避免除零。 |
| coretemp | Linux 提供的 Intel CPU 封装和核心温度监控接口，sysfs 读数单位为千分之一摄氏度。 |
| 温度监督 | 持续读取温度，达到项目阈值或监控失败时停止当前任务。 |
| 进程组 | 一组相关进程；温度监督只终止它启动的任务及同组子进程。 |
| 分项计时（profiling） | 分别测量计算阶段耗时，用于定位主要耗时。 |
| 行跨度（leading dimension） | BLAS 中相邻矩阵行或列起点间隔；这里用于直接访问交错存放的各注意力头。 |
| PWM / 占空比 | 脉宽调制及信号开启时间的比例，可用于控制风扇；读数不能直接换算为实际转速。 |
| RPM | 每分钟转数，风扇转速单位。 |
| BMC | 服务器管理控制器，可独立提供温度和风扇等硬件状态。 |
| IPMI | 读取服务器管理控制器信息的接口，本项目使用 ipmitool 的只读风扇查询。 |
| 风扇策略 | 根据温度等状态调节转速的规则；转速采样只能反映部分外部行为。 |
| 工作缓冲区复用（workspace reuse） | 预先分配计算临时内存，在相同形状的多次推理间复用，避免反复分配。 |
| 稳态延迟 | 完成初始化和预热后连续执行时的单次耗时，不包含首次创建成本。 |
| Valgrind / 内存检查 | 动态检查程序的非法访问、未初始化值读取和内存泄漏，本项目使用主机侧已有工具。 |
| AddressSanitizer | 编译器插入检测代码来检查内存越界等错误的工具，需要匹配的运行库。 |
| 页面触达 | 程序首次实际读写已分配的内存页；分配返回不代表所有页面已准备就绪。 |
| LLM / 语言模型 | 根据已有词元预测下一个词元的模型；小型训练模型用于验证同类推理路径。 |
| AVX-512 | CPU的一组512位向量指令；实际使用取决于软件实现及运行时选择。 |
| VNNI / DL Boost | Intel整数点积加速指令及其产品功能名称；需整数计算路径，不能直接等同于float32提速。 |
| 量化 / INT8 | 用较低精度整数表示部分权重或计算；需验证精度与性能，本轮暂不实施。 |
| MKL | Intel数学库，现有PyTorch CPU版本已带有其矩阵计算支持。 |
| 分词器 / 词元 | 将文本转换为模型词表编号的工具及其文本单位。 |
| GELU / gelu_new | 非线性激活函数；GELU 有基于误差函数 erf 的公式及 tanh 等近似，gelu_new 使用 tanh 近似。移植须匹配模型使用的版本，不能只因函数名字相同就认为计算一致。 |
| 局部注意力 | 只允许一个位置关注规定窗口内的历史位置；全局因果注意力允许所有过去位置。 |
| 贪心生成 | 每次选取输出分数最大的词元，继续预测下一个词元。 |
| eager执行 | 框架直接依次执行算子，便于做语义清晰的参考。 |
| 生成缓存 | 保存之前位置的注意力中间结果以避免重复计算；本轮先不用。 |
| Transformers | Hugging Face提供模型加载和参考实现的Python库，区别于Transformer网络架构名称。 |
| 常驻执行器 | 保持计算进程及模型权重存活，接受连续推理请求，减少反复启动与传输；本项目已在单VE槽位1实现。 |
| SHA256清单 | 为下载文件记录内容摘要并在加载时核对，用于检测文件改变，不等同于独立发布者签名。 |
| 二进制帧 / 会话 | 用明确长度和类型传递一次请求或响应；会话保持同一执行进程接受连续请求。 |
| 往返延迟 | 从发送请求到收到响应的时间，包含通信、调度和计算。 |
| 容量工作缓冲区 | 一次为最大序列长度分配临时内存，之后接受范围内不同长度请求，不重新分配。 |
| IPC / 管道 | 进程间通信；本项目通过本地标准输入/输出字节流传递请求，不开放网络端口。 |
| Q4 / 4位权重量化 | 用约4位编码每个权重，另有缩放等元数据；计算需要对应解码内核并验证精度。 |
| BF16 / FP8 | 16位和8位浮点格式；模型以某格式保存不代表VE内核已支持该格式。 |
| 稠密模型 / MoE（专家混合） | 稠密模型通常逐步使用各层主体权重；MoE按输入选择部分专家计算，但通常仍需保存全部专家。 |
| 激活参数 | 当前词元实际参与计算的参数，区别于模型保存的总参数；不能单独确定真实内存流量。 |
| 预填充 / 解码 | 预填充处理输入提示词；解码利用已有状态逐步生成新词元，性能应分别计量。 |
| KV缓存 / 循环状态 | 分别保存过去的注意力键值和线性注意力状态，避免每步重算全部历史。 |
| Gated DeltaNet | 带门控的线性注意力结构，用持续更新的状态表示历史，与普通Softmax注意力不同。 |
| RMSNorm / RoPE / 门控前馈 | 均方根归一化、旋转位置编码和用门控调节特征的前馈层，是本次目标模型需新增的计算。 |
| 带宽上界估算 | 用有效读取带宽除以每步读取字节数计算理想速度，忽略其他耗时，不能当作实测性能。 |
| llama.cpp / ggml | C/C++语言模型执行框架及其张量计算库；本项目正在评估其VE移植，不代表已经支持。 |
| GGUF | 保存模型配置、词表及量化权重的文件格式，便于推理框架直接加载。 |
| 工具链 / 交叉编译 | 用编译器及配套库把源码构建成目标架构程序；VE程序不能当作x86程序直接启动。 |
| 量化点积 | 直接利用低位权重及量化激活计算向量内积，避免整模型展开为float32。 |
| 链接期替换 | 构建程序时把指定函数调用连接到项目实现，保留上游源码，并可构建未替换基线。 |
| 强制同一词元输入 | 比较两个后端时让其处理相同的历史编号，以区分数值差异和生成路径分叉。 |
| UTF-8 | Unicode字符的字节编码；词元边界不一定是完整字符边界，输出JSON需处理末尾不完整字符。 |
| FP16 / half | 16位浮点数；本次量化格式用它保存缩放系数，区别于BF16。 |
| 非正规数 / 负零 | IEEE浮点表示中的极小非零值和带负号的零；低位缩放参数解码需正确处理。 |
| 工作集 | 某段计算实际访问的数据集合；超过缓存容量时，缓存内小矩阵结果可能无法代表大型权重。 |
| SGEMV | BLAS的单精度矩阵向量乘法接口，可用于逐词元生成的线性层。 |
| 分块反量化 | 每次只把一小块低位权重解码成浮点数供计算，避免整模型占用float32容量。 |
| 模型工厂 | 根据模型架构创建对应模型对象的代码；本次仅调整它的编译优化来控制构建时间。 |
| 节点耗时采样 | 在计算图的算子节点前后记录耗时，以定位瓶颈；逐节点观察会改变调度，正式性能测试需关闭。 |
| 跨设备张量切分 | 将同一权重或状态张量分到多个设备上计算；当前单VE专项构建不提供该功能，并非把同卡的线程并行禁用。 |
| 内联与内联属性 | 内联将函数体放到调用位置；属性可要求更强的内联。NCC分别以-fno-inline和-fno-inline-attribute控制它们，复杂模板的内联可能增加编译成本。 |
| 聚合初始化 | 以花括号为对象的成员指定初值；没有显式值的数组元素通常按规则初始化。等价默认对象复制必须保留非零默认成员，不能直接全部清零。 |
| C/C++语言链接 | 决定函数名称及函数类型的语言约定；C++名称通常包含参数信息，C接口名称通常不包含。NCC对回调指针的语言类型区分较严格，适配时需保持真实调用约定兼容。 |
| 常驻线程池 | 预先创建并反复使用的一组工作线程，避免每次计算都重新创建和销毁线程。 |
| RSS | 工具报告的驻留内存指标；不同工具的单位和统计范围须核对，不能直接当作模型权重总大小。 |
| restrict | C语言指针限定符，声明本次访问的缓冲不与其他相关缓冲重叠，帮助编译器优化；调用者必须遵守此条件。 |
| 原子变量 | 多线程读取或修改时保证单次操作完整的变量；用于安全记录中止回调调用次数。 |
| USS / PSS | USS是进程独占内存；PSS按附着进程数分摊共享内存。NEC文档说明VE的RSS由两者相加；采样峰值不等于全卡占用。 |
| 浮点运算重排 / 快速数学 | 编译器允许调整运算顺序或使用更快的近似数学实现；可能影响舍入误差，需要真实模型验证。 |
| 倒数替代 | 将除法转换为乘以倒数；向量指令的近似实现与直接除法可能产生不同舍入结果。 |
| FP64累加 / DGEMM / DGEMV | 使用64位浮点数累加乘积；DGEMM和DGEMV是双精度矩阵乘法和矩阵向量乘法。此处权重仍为原量化格式，激活存储仍是32位。 |
| 算子融合 | 将多个计算节点合为一次执行；高精度实验关闭RMS融合，以确保使用规定的归一化实现。 |
| SSM短卷积 | 状态模型在时间轴上对每个通道单独计算的小窗口一维卷积；本模型将历史窗口与当前词元组合后计算。 |
| 状态快照 | 保存某个输入步骤之后的完整历史状态，用于恢复或选择最近若干步；本次槽0保存最新状态。 |
| 分组头与序列广播 | 多个输出注意力头复用查询或键的头；多个序列按指定分组复用查询或键输入。 |
| 构建指纹 | 用源码、编译选项、库和执行器的哈希标识一次构建，以便确认测试实际运行的版本；不等同正确性证明。 |
| MiB / GiB / GB | MiB和GiB按1024进制计量，1 MiB=1048576字节、1 GiB=1073741824字节；GB按1000进制计量，1 GB=1000000000字节，容量比较须统一单位。 |
| 有界权重缓存 | 在明确容量上限内保存已解码的不可变权重，避免每次推理重复解码；不等同保存词元历史的状态缓存。 |
| 互斥锁 | 同一时刻只允许一个线程访问受保护的共享数据，防止并发修改产生错误。耗时工作放在锁内会限制并行度。 |
| 暂存区 / Git index | Git保存下一次提交内容的区域；发布审计读取这里的确切文件版本。 |
| 脱敏 / Redaction | 在公开前去除凭据、私人路径及其他不应发布的数据。 |
| noreply邮箱 | 用于提交身份的非收件邮箱，本轮以agent身份避免暴露个人邮箱。 |
| Q4_K_M | GGUF的一种混合量化方案，多数权重为4位K量化，部分张量采用更高精度；M为方案档位，不代表全模型固定4位。 |
| ABI / 应用二进制接口 | 编译后的函数命名、参数传递和对象布局约定；本次小型模型创建适配器限定已固定的上游修订与NEC编译工具链。 |
| 长度前缀协议 | 每条请求先传固定长度的消息头，说明后续文本字节数和生成数量，再传文本；支持换行与中文，不依赖换行划分请求。 |
| 请求往返耗时 | 主机从发送请求到收到完整响应的实际时间，包含通信、VE执行和响应输出。 |
| 线程耗时总和 | 将并行工作线程的时间区间相加；多个线程同时工作时可能大于实际经过时间，不能直接与单次请求耗时相加。 |
| 墙钟时间 | 从开始到结束实际经过的时间；并行执行时不能用各线程耗时之和替代。 |
| 冷态 / 热态请求 | 此项目中分别指需要建立权重缓存的首次请求，以及能够复用既有权重缓存的后续请求。 |
| 标准输入 / 标准输出 / 标准错误 | 进程默认的输入流、结果输出流和诊断流，分别常写作stdin、stdout、stderr；本入口用前两者传协议消息，将诊断单独留在本地。 |
| JSON | 使用对象、数组和基础数值表示结构化数据的文本格式；本入口每行输出一个完整JSON对象。 |
| 分组查询注意力 / GQA | 多个查询头共享同一个键值头；矩阵运算必须按正确分组映射头索引，不能简单重复取模。 |
| 张量步长 / stride | 相邻元素沿某个维度在内存中的字节距离；视图、转置或填充布局可能不连续，寻址必须使用实际步长。 |
| FP16舍入语义 | 将输入转为16位浮点数造成的精度取舍；本次注意力加速保留原后端的输入舍入，再用FP64累加。 |
| 矩阵分块 / tile | 将大矩阵拆成较小矩阵交给计算内核；分块大小会影响函数调用次数、数据打包成本和工作内存。 |
| 小端字节序 | 多字节数值先存最低有效字节；本项目请求头的两个32位整数使用这一顺序，避免主机与执行器解释不一致。 |
| AB 筛选 | 先运行基线 A，再运行候选 B 的初步比较；可筛除退化配置，但不能充分排除时间漂移。 |
| ABBA 交替复测 | 按基线、候选、候选、基线顺序比较，以减小运行先后和环境漂移的影响；本项目用于最终采用判断。 |
| 冷请求 / warm 请求 | 冷请求包含首次权重缓存建立；warm 请求复用已建立缓存，二者耗时需分别报告。 |
| 边界回归 | 针对分块边界、长序列和请求重置等易出错条件，重复检查行为与参考一致。 |
| 尾批 | 分批处理后剩余的最后一批；129、257 个输入词元在 128 大小分批下均留下单词元尾批。 |
| 线程累计耗时 | 把多个工作线程在某阶段的计时时长相加；线程可同时运行，因此数值不能直接当作用户等待的墙钟耗时。 |
| 计时扰动 | 读取时钟、更新计数等诊断操作本身造成的耗时变化；需用关闭计时的对照版本量化。 |
| 抽样计时 | 只计量部分计算块，以降低诊断开销，再按抽样比例估计总耗时；估计存在误差，需保留实际采样次数。 |
| 输入整理 / packing | 为计算内核复制输入、转换浮点类型或整理连续内存；本轮计时包含投影输入复制及 BLAS 前的 FP64 转换，不包含所有注意力转换。 |
| 激活值 | 模型计算过程中产生的中间数值；输入整理复用只能在有效计算范围内进行，不能把上一请求的中间数值当作下一请求输入。 |
| HBM / HBM2 | 高带宽堆叠内存及其第二代；VE 的本地内存，卡内带宽与主机 PCIe 传输带宽是不同指标。 |
| TB/s / GB/s | 每秒传输的数据量单位；厂商带宽通常采用十进制，1 TB/s = 1000 GB/s。GiB 是二进制容量单位，换算时需区分。 |
| MTP / Multi-Token Prediction | 多词元预测；需要训练得到的预测模块，为投机解码提供后续词元候选，候选需由目标模型验证。 |
| 投机解码 / speculative decoding | 先提出多个草稿词元，再由目标模型批量验证；拒绝时回退状态。首版使用贪心一致性验证，采样生成另需正确的接受与拒绝规则。 |
| 接受率 / acceptance rate | 草稿词元中通过目标模型验证的比例；需结合草稿计算、验证与回退成本判断是否提速。 |
| 递归状态快照 / recurrent-state snapshot | 为混合线性注意力模型保存近期位置的内部状态；草稿被拒绝时除普通 KV 外，也必须恢复这部分状态。 |
| 草稿追赶 / draft catch-up | 用目标模型真实隐藏状态重新计算草稿模型接受区域，令下一轮草稿基于正确的上下文。 |
| 张量借用 / tensor borrowing | 两个模型引用同一份不可变权重张量；需先验证内容一致，并确保权重所有者比借用者活得更久。 |
| 填充词元 / padding token | 为对齐批次长度补入的占位词元；本轮单序列 MTP 不输入填充，但模型文件的分词器设置仍统一采用目标模型。 |
| 隐藏状态 / hidden state | 模型内部的向量表示；原生 MTP 使用目标上一位置的隐藏状态与当前词元来提出后续候选。 |
| 占空比 / duty cycle | 在每段时间内允许运行的时间比例；当前图像单任务编译在温度守护下使用 50%，CPU 参考当前降为 10% 且与编译串行；早期单例参考为 25%，编译曾试验 75%。只暂停任务子进程，不修改风扇或 CPU 固件配置。 |
| 自适应 MTP / adaptive MTP | 在当前请求中测量普通解码与草稿验证的单位词元成本，若草稿收益不足就停用 MTP；不会改变目标模型选择的贪心词元，策略仍需用实际工作负载验证。 |
| 稠密模型 / dense model | 每次前向计算使用主干中常规的全部层参数；相对 MoE，不按输入选择少数专家。 |
| 扩散模型 / diffusion model | 通过多轮去噪，把噪声表示逐步变为图像或视频；生成步骤不同于语言模型逐词元解码。 |
| 扩散 Transformer / DiT | 使用 Transformer 作为扩散去噪主干，在一轮中处理多个图像或视频片段表示。 |
| VAE / 变分自编码器 | 在像素与更紧凑的潜在表示之间转换；图像或视频生成常在潜在表示中去噪，最后再解码成像素。 |
| 分块注意力 / tiled attention | 分块计算注意力并组合归一化结果，减少完整注意力矩阵的工作区需求；仍需验证数值精度与具体实现效率。 |
| U-Net | 图像去噪网络的一种结构，逐级降低与恢复特征分辨率，并通过跳跃连接保留细节；SD-Turbo 使用这类主干。 |
| SGEMM | NLC 等数学库中的 FP32 矩阵乘法接口；与此前用于高精度累加的 DGEMM 不同。 |
| 初始噪声 / initial noise | 扩散生成开始时的随机潜在数组；跨 CPU/VE 验证时使用同一导出数组，避免随机数实现差异。 |
| 归一化 L2 误差 | 差异向量的 L2 长度除以参考向量的 L2 长度，分母设下限；用于比较整体数值偏差，还须同时检查最大绝对误差。 |
| NCHW | 张量轴按批次、通道、高度、宽度排列；连续数组中宽度变化最快。原生 ggml 常以相反顺序描述最低连续轴，比较时须明确布局。 |
| 输入块整理 / im2col | 把卷积的邻域数据整理成矩阵，再用矩阵乘法计算；能复用数学库，但完整展开可能需要很大的工作区。 |
| Euler 调度器 / Euler scheduler | 根据当前噪声强度和网络预测更新潜在表示的数值方法；时间步、噪声缩放和预测类型都要与参考实现匹配。 |
| 提示引导 / CFG | 结合带文本条件与无条件预测以加强提示影响；SD-Turbo 的初始验证关闭这一混合。不同框架的关闭参数可能不同，须比较实际计算而不只比较参数数值。 |
| ε 预测 / epsilon prediction | 去噪网络直接预测潜在表示中的噪声分量；与预测干净样本或速度的模型不同，调度更新公式必须匹配这一类型。 |
| GEGLU | 用 GELU 激活一部分特征作为门控，再与另一部分相乘的网络层；SD-Turbo 的去噪网络包含这种计算。 |
| erf / 误差函数 | 与高斯曲线积分有关的数学函数；官方 SD-Turbo 的 GELU 用它计算激活，而某些实现用 tanh 近似或半精度查表。 |
| CLIP | 将图像和文本学习为可对应的特征表示的一类模型；SD-Turbo 使用其中的文本编码器，把提示转换成去噪网络的条件。 |
| SD2 / Stable Diffusion 2.x | 潜在扩散图像模型系列；本项目首阶段的 SD-Turbo 基于 SD2.1 架构，通过蒸馏减少生成步数。 |
| T5 | 把语言任务统一为文本输入与文本输出的一类 Transformer 模型；部分图像模型使用其文本编码器，本轮 SD-Turbo 不使用。 |
| FP32 / 单精度浮点 | 每个数使用32位表示的浮点格式；本轮图像权重及卷积输入展开保持该精度，内存有效载荷与工作区分别计算。 |
| 可变参数宏 / variadic macro | 可接受不同数量参数的预处理宏；本次将日志格式串也纳入整个参数包，避免依赖省略空参数时删除逗号的编译器扩展。 |
| 超分辨率 / super-resolution | 将图像放大并预测细节的处理，可能使用额外神经网络；本轮验证原生512×512输出，不验证该可选功能。 |
| 模型工厂 / model factory | 根据模型类型和配置创建对应执行器的代码；创建成功不等于数值或硬件验收通过。 |
| 张量索引 / tensor index | 记录每个权重张量的名称、形状和文件字节偏移的目录；解析索引不执行模型计算，本轮读取原始FP32权重而不改写它们。 |
| C++11 / C++17 语言标准 | C++在2011年与2017年制定的语言规则版本；旧图像框架要求C++11，不同版本可能走编译器中的不同实现路径，版本较新不保证更快或兼容更好。 |
| 模板实例化 / template instantiation | 编译器根据具体类型，把C++通用模板生成对应代码的过程；类型组合较多时可能增加编译时间和内存，但不等于推理计算量增加。 |
| 汇编输出 / assembly output | 编译器生成的目标处理器指令文本；后续还需汇编和链接才能成为可执行程序，看到输出增长不等于模型已经运行。 |
| SIGTERM / 终止信号 | 请求进程结束的操作系统信号；本轮主动停止确认身份的编译任务使用它，不应记录成编译器自行崩溃。 |
| SIGSEGV / 段错误信号 | 程序发生非法内存访问时常见的终止信号；本轮较新框架编译器曾出现，不等于模型误差或温度停止，也不能仅凭信号确定根因。 |
| CPU亲和性 / CPU affinity | 限定某个进程或线程可在哪些CPU核心运行；本轮把参考任务与编译分配到不同物理CPU，属于单任务调度，不修改风扇或固件策略。 |
| trailing 时间步间隔 | 从训练时间步序列末端向前选取推理时间步的调度方式；本轮官方单步使用999，四步使用999、749、499、249。 |
| SDK / 软件开发工具包 | 含编译工具、库及调用接口的开发组件集合；本轮固定图像验证入口只支持已明确的流程，不等于完整上游SDK兼容。 |
| 后端分段计时 | 累计调度器交给同一计算后端的每段执行耗时；图执行还可能包含输入复制和同步，不能把嵌套计时重复相加。 |
| 显式编译依赖 | 直接告诉构建系统哪些头文件改变时必须重编译对象文件；用于补足本机编译器依赖记录遗漏，避免旧代码混入新二进制。 |
| 单调时钟 | 用于测量经过时间的时钟，不随系统日历校时回拨；本轮用于阶段耗时测量。 |
| 自旋等待 | 工作线程反复检查是否有新任务，会消耗计算资源；本轮候选设置poll=0，无任务时阻塞等待唤醒。 |
| 张量布局变换 | 调整多维数组各维的排列或连续存储方式，可能只改变视图，也可能实际复制数据；必须区分两者的耗时。 |
| CMake | 根据项目依赖和编译规则生成构建任务的工具；本轮增加显式头文件依赖。 |
| 对象文件 | 单个源文件编译后的机器码文件，通常以.o结尾；链接器将它们组合成最终程序。 |
| 算子级计时 | 分别累计卷积输入整理、归一化、激活等操作的耗时，用于定位后端总耗时中的具体瓶颈。 |
| 同步屏障 | 多个工作线程等待彼此完成当前阶段后再继续；本轮节点计时包含结束屏障的等待。 |
| SiLU | 逐元素激活函数，计算 x/(1+exp(-x))；本轮隔离向量循环并保留 FP32 运算。 |
| 向量数学范围检查 | 向量数学函数检查极端输入并处理溢出或下溢；NCC默认关闭，不能用标量fast-math选项替代。 |
| 顺序求和 | 按元素原来的顺序逐一累加，避免并行归约改变浮点舍入；本轮Softmax保持双精度顺序累加。 |

| mmap / munmap | 映射和解除映射内存的系统接口；本轮用它们控制真实映射生命周期，区别于可能保留分配器缓存的 malloc/free。 |

| 离散采样最高值 | 固定间隔读取的多个测量值中的最大值；采样之间可能出现更高的瞬时值，因此不能等同真实瞬时峰值。 |
| 引用计数 | 记录有多少对象仍持有同一资源；本轮共享线程池只在流水线和全部组件都释放引用后销毁。 |
| 共享计算线程池 | 多个顺序执行的模型组件使用同一组工作线程；权重和模型后端仍可分别保留，避免为每个常驻组件保留一组线程。 |
| SIGSEGV / 段错误 | 进程访问无效内存时通常收到的终止信号；本轮曾在请求行解析中实际复现，不能把它当作数值验收失败或正常结束。 |
| 惰性初始化（lazy initialization） | 首次实际使用时才创建对象；本轮分词器首次请求构造，后续顺序请求复用，组件关闭时释放。 |
| 归约（reduction） | 将多个数合并成一个结果，例如求和；多线程可能改变合并顺序与浮点舍入，需要独立数值对照。 |
| GEMM 的 m/n/k | 矩阵乘法输出的行数m、列数n和点积长度k；探针必须同时匹配转置与行跨度，才能代表实际调用。 |

| 误差函数（erf） | 数学特殊函数，GELU用它计算平滑缩放因子；erff是单精度版本，向量实现需要独立验证精度及特殊值行为。 |
| 编译优化等级（-O1 / -O2） | 编译器优化代码的不同等级；-O2通常允许更多优化，但是否向量化和最终性能必须检查实际编译命令并实测，不能只看构建配置。 |
| 输出分区所有权（output partition ownership） | 每个线程负责写入哪些输出位置的约定；区间互不重叠可避免同时写同一位置，测试还需检查区间外保持不变。 |
| 空分区（empty partition） | 当线程或分区数超过任务行数时，某些线程没有分配到输出；它们必须返回且不写入任何数据。 |
| 连续布局整理（CONT） | 将张量复制或转换为连续存储布局，便于后续计算；本项目按算子计时区分其数据搬运开销。 |
| 空间维度分块 | 将卷积展开后的空间位置分成多个矩阵调用，保留输入偏移及原输出步长；不同形状可能提速或退化，需要实测。 |
| 像素打包（pixel packing） | 把分开存储的红、绿、蓝浮点像素转换为交错的RGB字节，供图像编码使用；需要保持截断和舍入规则一致。 |
| PNG | 一种无损图像文件格式，编码压缩不会改变解码后的像素值；编码耗时需要与模型计算分开测量。 |
| RGB | 红、绿、蓝三个颜色通道；本项目把三个浮点平面转换成交错的三个字节，再交给PNG编码器。 |
| 像素范围限制（pixel clamping） | 将像素数值限制到指定范围；这里把解码值映射并限制到0到1，之后按原有舍入规则转换为字节。 |
| 静态目标 / 静态库（static library） | 将一组代码单独编译成库并链接进最终程序；本项目用它给PNG编码器设置独立优化等级，同时保留主程序的原编译配置。 |


### RGB 输出缓冲复用

RGB 表示红、绿、蓝三个颜色通道。输出缓冲复用指一个进程保留像素字节数组供后续请求使用，减少重复分配和初始化；每个请求必须覆盖全部像素，避免残留数据。该措施的性能收益需要实测。


### 像素钳制与打包

钳制（clamp）指将像素值限制在指定范围，例如 0–1；打包（pack）指将分开的浮点红、绿、蓝通道按原舍入规则转换成交错排列的 RGB 字节。优化时必须保留极值检查和原输出语义。


### 循环重排与有效前缀

循环重排指调整嵌套循环的执行顺序，例如先选择颜色通道，再遍历所有像素，以改变数据访问方式；每个输出必须仍使用原计算规则。有效前缀指数组中首个异常元素之前的连续部分，本项目像素钳制失败时仅修改这一部分，异常元素及其后面的原始字节保持不变。


### 最小位置归约

归约（reduction）指把多个元素的信息合成为一个结果。最小位置归约在这里指找到全部异常元素中最小的数组下标，即首个异常位置；不存在异常时返回数组长度，用于保留原像素钳制的部分写入行为。


### 按位或归约

按位或归约把多个整数标记用或运算合并；本项目用 0 表示有限、1 表示异常，最终结果非零即表示至少有一个异常。先检查是否有异常、仅在异常时定位首个异常，可保留原有输出行为；能否向量化及性能收益必须实测。


### 浮点位模式与次正规数

浮点位模式指浮点数在内存中的原始二进制表示；按位分类必须先核验表示格式，并使用安全的字节复制，不能破坏原数据。次正规数是非常接近零、低于正常表示范围的有限浮点数，有限值检查必须接受它们；NaN 和无穷值应拒绝。

### 部分向量化与 NaN 位模式

部分向量化指编译器只把循环的一部分转换为向量指令，不能称为整个扫描完全向量化。IEEE binary32 是32位浮点表示，指数位全1代表无穷或NaN（非数值）；信号NaN和静默NaN具有不同原始位模式，本轮检查分类与未修改尾部的字节保持，不承诺浮点异常标志相同。

### 双构建交替对照

双构建交替对照使用两份固定来源的模型二进制按原版/候选/候选/原版顺序执行，以比较一项构建变化；必须核验其余源码、权重、运行配置一致。它不是同二进制比较，链接后函数位置和缓存状态仍可能不同。本轮用原隔离O2与新位模式模型比较，避免把此前O0到O2的收益重复计入。

### 整数截断与半整数舍入阈值

整数截断指去掉小数部分；非负数可通过与截断整数加0.5比较，决定是否向上取整。半整数是0.5、1.5等带半个单位的数。此处阈值可精确表示；直接给缩放值加0.5可能先发生浮点舍入，必须用阈值两侧的相邻浮点数验证输出。

### 二维转置拷贝与合并连续尾维

二维转置拷贝指把矩阵按行、列互换的位置复制到另一个缓冲区，只改变存储布局，不做数值运算。合并连续尾维指后面的多个维度在内存中连续时，用一个维度统一索引；必须按实际字节步长确认连续性，不能仅凭形状推断。本轮 CONT 候选将符合条件的多维布局整理视为二维转置，尚未完成新核验证或证明提速。

### 拷贝测试中的哨兵、uint32与图回调

哨兵是在缓冲区边界或未分配给当前线程的区域放置的固定位模式，用于检查越界或错误写入。uint32是32位无符号整数，本轮用它读取float32的原始位模式来验证复制，不把浮点数转换成整数数值。图回调是由计算图运行时调用的自定义函数；本轮候选和原CONT共享同一图运行时，但算子类型不同，因此独立图计时不能直接当作完整模型收益。

### 次正规结果清零（FTZ，flush to zero）

把低于最小正规范围的非零浮点结果变为零，可能保留正负符号；与IEEE渐进下溢保留次正规数的结果不同。本项目第84轮在VE基线和候选缩放中实际观察到这种行为，不能把“二者按位相同”当作严格IEEE正确性通过。

### 分组归一化（GroupNorm）

把通道分成若干组，分别按组的均值和方差调整数值，用于图像网络中的特征归一化。实现还加入小正数epsilon避免除零；改变求和顺序可能改变浮点结果，本项目候选应先保持均值/方差计算顺序，仅验证最后缩放阶段。

### 静默批量计时

静默批量计时是在计时阶段关闭逐次诊断打印，将多次相同计算放在一个计时区间内，再除以执行次数取得平均每次耗时。它减少打印和读时钟对短计算的干扰；正确性阶段仍保留诊断。本项目第90轮每个计时样本执行16次实际图计算，输出在批次结束后核验，不将9216次调用表述为9216次逐次输出比较。

### 中心化与平方暂存

中心化是对每个值减去该组均值；方差计算还需要把中心化后的值平方。将这两步先向量计算并写入每线程独占的固定大小暂存，再依原顺序累加，可以保持累加顺序，同时让逐元素计算使用向量指令。第91轮暂存2048个FP32平方值，大小8KiB；块边界必须对应完整行，其他情况回退原路径。

### 按形状分块（mixed4096）

本项目的显式VAE矩阵分块模式：仅将已验证的256×65536×2304和256×65536×4608矩阵分成4096列调用，其余已采用形状仍为8192列；不代表所有矩阵统一使用4096，也不代表完整模型已经提速。

## 增量形状分块（mixed2048）

显式候选配置：保留mixed4096，将已测受益的512×16384×4608矩阵按空间维度2048分块；其他未列形状仍完整计算。名称不代表所有矩阵统一使用2048。模型派发及完整请求收益需分别验证。

## 线程再创建（thread regeneration）

运行时释放原有线程并重新创建线程。NEC编译器FAQ指出线程数量变化可能发生这一过程；它可能增加配置切换耗时。项目的线程恢复计时还包含其他操作，不能仅凭计时认定全部由线程再创建造成。

## VAE整阶段4线程（all4）与选择性矩阵4线程（selective）

all4令VAE通用计算和矩阵库都使用4线程，图间保持4，下一请求CLIP再切回8；selective令VAE通用计算使用8线程，每个矩阵图切到4后恢复8。比较会同时影响通用计算和线程切换，不能解释为纯矩阵库优化。

### 输出通道分块

卷积矩阵乘法的输出行对应输出通道。输出通道分块将这些行拆成若干批分别计算，空间维度分块保持既有配置，K维（输入通道与卷积核元素）仍完整求和。它可能改变矩阵库的打包及计算效率，也可能因重复打包和更多调用而退化，必须先独立验证再测完整模型。

### 矩阵输入预排列（pre-transpose）

将原矩阵N×K的元素预先重排成K×N，并使用匹配的新矩阵乘法参数；数学值不变，物理访问顺序改变。候选必须计入重排、缓冲准备和乘法的总成本，不能把乘法单独变快当作整个流程变快。新的归约路径是否保持模型精度与输出字节，需要实际验证。

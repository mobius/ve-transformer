# 迭代 008：分项计时与注意力后端进展

分项计时（128×256，槽位 1，20 次，启用仪器）：平均总 14.519350 ms，attention 14.094200 ms（约 97%），allocation 0.194400 ms、QKV 0.048400 ms、FFN 0.097600 ms，其余模块均较小。此次 CPU 峰值 64°C、VE 峰值约 39–41.25°C。

新增 fast 后端：NLC 每头两次 SGEMM，直接使用交错头数据的行跨度；单张 t×t 分数矩阵复用，稳定 Softmax 和因果尾部置零。保留原 base 和仅线性 NLC 后端。新增 profile API 不使用全局状态，普通 vt_forward 不读分项时钟。

首轮受温度监督的三卡测试在节点 2 大形状验证中被正确中止（退出码 125）：CPU 观测峰值 76°C，高于 75°C 停止阈值；VE 峰值 43.12°C、39°C、41.62°C。不提高温度阈值，等待 CPU 冷却再继续。此次监控记录 build/results/20261002T065043Z-temperature-fggfbi_z.csv。

中止前槽位 1 的独立参考验证全部通过，128×256 平均由线性 NLC 14.456820 ms 降至 fast 0.920600 ms；256×512 由 63.656500 降至 2.874700 ms。完整三卡结论尚未取得，不能把部分结果当成全部验证。

为减少验证自身发热，CPU 基础 float32 的漂移诊断改为显式 --cpu-diagnostic 选项；默认仍做完整独立 NumPy float64 逐元素比较，没有降低数值判定标准。此前反复执行低效 CPU 参考已无必要，不用 CPU 结果替代高精度真值。

恢复后的三卡验证全部通过：30 个多形状对照和 6 个小参考；三档相对上一版 NLC 加速约 3.3、15.8、22.2 倍。fast 的 PyTorch 18 个对照最大误差 9.23e-7；三卡两层模型最大输出分数误差 3.35e-7，argmax 全部一致。模型未训练。

分项计时：128×256 总延迟 0.929933 ms，注意力 0.496533、分配 0.203233 ms；256×512 总延迟 2.8864 ms，注意力 1.162650、分配 0.806850 ms。分配已成为明显成本，后续可独立验证工作缓冲区复用。当前未实现此优化。原始结果在忽略提交的 build/results。

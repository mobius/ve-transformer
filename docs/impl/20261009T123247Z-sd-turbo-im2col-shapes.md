# VAE im2col真实形状采集

本轮先采集实际卷积展开形状，不改变数据排列算法。已有GELU诊断中VAE im2col热耗时0.839677秒/40节点；这是含计时开销的历史诊断，不是本轮收益。

实施前温度保护检查通过：CPU59°C，VE最高40.75°C；96逻辑CPU、三张VE、NCC/ve_exec可用，运行槽及VEOS接口存在；设备可见不等于本轮运行验证。97可读风扇状态无变化。继续CPU80/85、VE70/75监控，缺失读数停止，不调整风扇。

添加默认关闭的--im2col-shape-profile，记录组件、输入/输出尺寸、卷积核、步长、填充、膨胀、线程数和候选资格；只在工作线程0输出，不记录张量值、地址或凭据。此诊断有额外日志开销，不用于正式性能比较。当前仅源代码准备完成，构建与VE双请求验证待执行。

下一步：保持已验证的通用8/VAE矩阵4、GELU与广播加乘配置，串行构建后执行双请求CPU参考验证；汇总VAE各真实形状及搬运字节数，再比较按输出连续写入与现有通道划分方案。必须验证填充、步长、边界、线程所有权和按位一致性后，才测整图收益。

## 本轮完成结果

构建与原生双请求均退出0，10项独立CPU参考检查通过。诊断记录43种组件/形状组合，UNet共196次、VAE共80次，与原有派发计数完全一致。VAE每请求40次、11种形状，输出逻辑写入量19.391235GiB/请求；512×512、3×3、128通道每请求6次，每次1.125GiB；256通道每请求2次，每次2.25GiB，二者合计11.25GiB/请求，约58.02%。这不是HBM实测流量或带宽，未计算本轮性能提升。

测试CPU最高69°C、VE最高50°C，97可读风扇状态无变化；不足以确认物理风扇策略。详细尺寸与原始摘要见[机器结果](../results/20261009T123247Z-sd-turbo-im2col-shapes.json)。

下一步优先针对上述两种512×512形状进行代表性单算子对照，研究输出位置划分与连续写入：保持原输出排列，按独立输出位置划分所有权，避免跨线程写入重叠；先以标量独立参考检查填充/步长/特殊浮点位模式及线程边界，再比较实际VE耗时。原实现保留，未证实更快前不接入模型。

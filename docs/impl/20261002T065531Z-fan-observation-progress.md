# 迭代 009：策略修改与观察进展

分设备默认阈值和风扇侧车 CSV 已实现，AGENTS.md 同步最新用户指示。首个完整只读采样：CPU 64°C，VE 峰值约 38.88–41.25°C；96 个可观测控制/状态通道，无变化。这只是启动时快照，不代表负载期策略。

模拟保护测试再次通过，新增 CPU/VE 不同默认阈值和 RPM/PWM/不可用风扇读取检查。没有写入 sysfs 控制节点。

风扇初次读取的暂时不可用值触发 Python 3.6 TypeError，发生在启动命令前；已修正为标记 unavailable。温度通道出现同类错误时则明确停止，不降低温度保护。

后续在实际 fast 框架验证和冷却采样中记录观察结果；BMC 实际转速仍缺少读取权限，不补写未测数据。

实际框架负载及5秒冷却观察：CPU峰值73°C，三卡峰值42.75/39/41.25°C；96个已有风扇/控制/服务通道未观察到变化。随后获得用户授权，以交互认证读取BMC风扇，七个前置风扇为3800–4000 RPM。认证信息未保存。增加 --bmc-fans 可选只读查询，使用sudo -n，不会提示或保存凭据；最多3秒超时，每约5秒一次。BMC不可用记录状态，不影响既有温度停止保护。

完成同一终端授权后的实际负载和5秒冷却观察：104个通道，CPU峰值68°C，VE峰值42.75/39.12/41.25°C。BMC前置风扇1在3800和3900 RPM之间变化，结束回到3800；其余已采样风扇转速及sysfs控制值和NEC服务状态无观察到变化。不能由100 RPM变化判定内部策略变更。首次跨终端查询没有可用sudo缓存，明确记为unavailable；随后同终端授权读取成功，无权限配置修改。

BMC解析与超时模拟测试、原温度保护测试通过。代码/文档敏感信息扫描及git diff --check通过；原始采样在忽略的build/results中。

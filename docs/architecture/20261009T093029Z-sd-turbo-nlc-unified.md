上一轮有实测进展：UNet三图线程准备82.360631秒、释放3.346735秒，候选未通过验收。本轮目标是通用后端和NLC使用同一OpenMP运行时、固定8线程，避免两套工作线程与逐BLAS图重设。尚未构建、未验证收益。

环境：宿主x86_64/96逻辑线程，ASPEED显示，三VE槽设备及VEOS套接字可见；沙箱没有设备链接，不能据此判定宿主不可用。NCC/ve_exec可用，前轮已实际执行。实施前独立温度守护查询VE槽1内存128MiB，CPU60°C、VE43°C、97风扇状态通道无变化；未发现旧重型任务。新调度路径仍须硬件测试。

源码依据：固定ggml通用后端已有GGML_USE_OPENMP路径，使用同一库的并行区域和屏障；采用本地生成覆盖，不修改vendor。CMake只为通用后端增加宏与-fopenmp，保留原数值优化级别；默认仍顺序NLC和原线程池。固定线程候选必须显式开启；记录实际构建标志、通用区域人数、BLAS区域人数与退出上限。原失败构建完整归档。

验收：先低占空比守护构建，再固定双请求独立CPU数值检查及温度/风扇/内存回收；通过后扩展六提示、四步与完整性能对照。不同二进制对照须说明边界，不能借微基准或线程容量推断全图收益。每轮输出报告，未测指标明确待验证；不提交、不推送。

## 实施记录

显式SD_GGML_OPENMP=1构建选项要求OpenMP NLC；通用CPU目标添加GGML_USE_OPENMP宏和-fopenmp，原GGML_OPENMP自动发现保持关闭，避免编译器探测差异。构建清单读取实际flags.make核验标志，并记录generic_thread_runtime；NLC固定模式保持8而不出图重置。检查器新增unified模式，启动OMP/VE_OMP均8，逐通用图及BLAS图核验实际区域人数、最大人数和后端调用次数，保留独立CPU输出验收。共享池日志仍代表共享调度元数据的生命周期，不再据该日志宣称通用pthread工作线程存在。构建进行中；未完成任何新调度路径硬件验收。

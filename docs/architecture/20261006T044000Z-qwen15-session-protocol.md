# Qwen 1.5B 常驻请求架构

主机 `python/qwen_session.py` 管理一个 `ve_exec` 子进程。VE 加载模型并创建上下文后输出 ready JSON；stdin 每条请求为两个小端无符号32位整数（UTF-8字节长度、生成上限）加文本正文。stdout 每条响应一行JSON。文本最长1 MiB，生成数量1–1024，还必须满足上下文容量。正常EOF结束；截断或超限请求使执行器报错退出。仅串行请求，没有网络服务。

每条请求在VE上分词，清空模型状态，再进行输入计算与逐词生成；请求不继承对话历史。模型、线程池、展开后的不可变权重缓存跨请求保留。主机只做提示模板拼接、协议传输、结果接收；分词与模型运算仍在VE。GGML日志中的CPU是后端名称，此处使用VE本地构建，不代表回到主机CPU进行模型运算。模型依旧Q4_K_M存储，展开缓存使用既有FP64精度路径，不改变数值运算。

`tokenize_seconds` 包括两遍分词和输入容量验证；`reset_seconds` 是上下文状态清理；`prefill_seconds` 包含首请求遇到的权重缓存建立；`model_decode_seconds` 是生成循环内提交及模型运算；`selection_seconds` 包括有限值检查和最大分数选择，启用trace时也包含分数写出；`text_conversion_seconds` 包含词元转文本与拼接。`decode_seconds` 保留原循环整体口径。`request_seconds` 从已收到完整请求开始至JSON输出前，排除接收、完整输出和刷新；主机`host_roundtrip_seconds`包含通信与输出。加载和上下文建立仅在ready中报告一次，响应重复携带这些数值只是启动元数据，不能每次累加。

`cache_fill_thread_seconds` 是成功缓存填充中分配、转换到稠密FP64及重新取得互斥锁的线程区间总和，不包括之前的量化解码，也不等于缓存建立的墙钟时间。其耗时已包含在相应模型阶段内，不可再次加到请求耗时。`cache_new_entries` 用于识别冷态和热态。

`QWEN_TIMING` 改变缓存统计结构布局，独立构建必须同时重新编译main和hook。原已验证二进制与归档不覆盖。客户端超时或协议错误后关闭该进程，禁止继续使用状态不明的会话。stderr写本地日志，避免管道堵塞；日志不自动发布。

# 每组件常驻线程池

CLIP/UNet/VAE各自的原生VE通用后端可绑定一个组件拥有的线程池。调度器在NLC与通用VE之间分段，通用分段共用该池；NLC阶段空闲线程阻塞，组件析构先释放后端，再销毁用户拥有的池。UNet保持到全部去噪步骤结束，因此四步也复用该池。

这不是跨请求常驻权重或图像服务：CLIP与VAE函数结束后释放参数，UNet去噪结束后释放；固定入口仍需噪声、调度及诊断目录。--threadpool persistent启用候选，disposable保留旧线程生命周期。

计时为嵌套包含关系。graph_compute包括输入复制、各后端执行及同步；backend_CPU指原生VE通用后端，绝非主机CPU；backend_BLAS是NLC。weights_load包括参数分配/读取，pipeline_total包含其他组件初始化、分词和输出。性能对照使用同一带计时二进制及诊断设置；计时开销未单独测量，不能据此推导未加入计时的生产流程性能。

显式CMake头文件依赖解决本机NCC增量构建的依赖遗漏，不更改数值内核编译优化等级。现代图像框架、其他提示的优化收益、三卡协同、物理HBM峰值及跨请求服务仍不在本轮验收范围。
